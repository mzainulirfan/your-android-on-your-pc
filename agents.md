# AGENTS.md — Your Android on Your PC

Panduan kerja untuk AI agent. Baca dokumen ini sebelum mengubah kode.

## Produk

Aplikasi desktop Windows untuk mengontrol Android dari PC: mirroring layar, input mouse/keyboard, screenshot, clipboard, transfer file dua arah, dan (fase berikutnya) notifikasi. Nama internal: **YAOP**.

## Stack (sudah dikunci)

- **Desktop shell:** Tauri 2 + Rust
- **Frontend:** Svelte 5 + TypeScript + Vite + Tailwind CSS 4
- **Android control:** ADB + scrcpy (proses eksternal terkelola)
- **Penyimpanan:** file konfigurasi lokal; tanpa database/server untuk MVP
- **Target:** Windows 10/11, USB + Wi-Fi

## Struktur

```text
apps/desktop/            frontend Svelte (Vite)
apps/desktop/src-tauri/  backend Rust + Tauri
binaries/adb/            (opsional) adb.exe lokal
binaries/scrcpy/         (opsional) scrcpy.exe lokal
docs/                    PRD, arsitektur, roadmap, keamanan
```

## Perintah

Jalankan dari `apps/desktop`:

```bash
npm install
npm run dev        # Vite saja (tanpa Tauri)
npm run tauri dev  # aplikasi desktop (butuh Rust + MSVC Build Tools)
npm run build      # build frontend
npm run check      # svelte-check
cargo check --manifest-path src-tauri/Cargo.toml
```

## Aturan kerja

1. **Scope MVP dulu.** Jangan menambah fitur di luar fase yang sedang dikerjakan (lihat `docs/ROADMAP.md`).
2. **UI tidak menjalankan shell bebas.** Semua operasi lewat command Rust yang tervalidasi.
3. **Jangan interpolasi string shell.** Argumen ADB/scrcpy selalu dikirim sebagai argumen terpisah; serial perangkat divalidasi.
4. **Satu modul, satu tanggung jawab.** Jangan menumpuk logika device, session, transfer, dan clipboard dalam satu file.
5. **Tanpa cloud, tanpa root.** Tidak ada telemetri atau pengiriman data keluar secara default.
6. **Error harus terlihat.** Setiap kegagalan ADB/scrcpy menghasilkan pesan yang bisa ditindaklanjuti, bukan `unwrap()`.
7. **Cleanup proses.** Proses scrcpy/ADB yang dijalankan aplikasi harus dihentikan saat sesi berakhir atau aplikasi keluar.
8. **Tanpa dependency baru yang tidak perlu.** Diskusikan dulu sebelum menambah crate/package besar.
9. **Bahasa:** kode dan identifier berbahasa Inggris; teks UI berbahasa Indonesia; dokumentasi berbahasa Indonesia.
10. **Kunci layar disimpan hanya atas permintaan.** Ketik manual dikirim sebagai satu operasi dan tidak pernah ditulis ke log. Menyimpan PIN/password adalah aksi eksplisit per perangkat (centang **Ingat** lalu Kirim di panel; kunci baru disimpan setelah verdict unlock menyatakan berhasil, jadi kunci yang salah tidak pernah menjadi chip): blob DPAPI milik akun Windows ini, maksimal 4 per perangkat / 24 total, dan yang keluar ke UI hanyalah `id`, label, metode, serta panjangnya — bukan nilainya. Kunci tersimpan dipakai otomatis sekali saat panel dibuka dalam keadaan terkunci (atau saat tombol Bangunkan mendarat di layar kunci): hanya kunci terbaru, satu percobaan per reveal, tanpa mengulang kunci lain supaya jatah percobaan HP tidak habis.

Setelah tap: ≤2 dump ulang (jeda 600 ms) mencari **tepat satu** affordance kirim (`/id/send` atau `Button` ber-text/desc persis `Kirim`/`Send`); kalau baris picker sudah habis dan string `mCurrentFocus` berubah → dianggap terkirim (build lama mengirim langsung di tap baris), kalau string-nya sama → `Aborted` (tap tidak mendarat di mana pun). `Finish` adalah satu-satunya jalur yang mengetuk. **Waktu**: satu `uiautomator dump` terukur **3,4 dtk** (bukan 0,5–2 dtk seperti asumsi awal) dan berbagi adbd dengan stream mirror, jadi `settle_on_picker` tidak lagi dump tiap ronde — satu probe fokus murah (merangkap guard layar: layar mati ⇒ `mCurrentFocus=null` ⇒ batal) lalu **maksimal 2 dump**; satu `Deadline` (12 dtk USB / 20 dtk Wi-Fi, `serial.contains(':')`) kini diperiksa **di dalam settle juga**, dengan dua catatan berbeda: sebelum tap ("YAOP berhenti sebelum mengetuk" = tidak ada yang tersentuh) vs sesudah tap ("lihat layar HP, gambar mungkin masih antre"). Target tersimpan di `chat-targets.json` (template sama dengan credentials/`wireless-devices.json`: **satu tujuan aktif per (serial, package)** — pilih baru mengganti, cap 16, parse gagal ⇒ dibaca kosong dan tidak pernah ditimpa). Event `chat-picker` (`reason: new|not-found|ambiguous|stale`) **hanya membawa label** — koordinat tidak pernah sampai ke UI, dan perintah `pick_chat_target` men-dump + mencocokkan ulang dari data segar, jadi klik chip tidak bisa mengetuk posisi basi; kalau daftar berubah di antara waktu, `resolve_by_choice` emit `stale` dan menolak tap. Guard keamanan tidak berubah: serial divalidasi di setiap masuk (paste, perintah, store), `package` dari dump divalidasi `is_safe_package`, dan label chat tidak pernah masuk command line (hanya `u32` koordinat). UI: satu baris chip di bawah toolbar kolom mirror (auto-hilang 25 dtk, dibersihkan bersama `pasteNote` saat sesi mulai/berakhir, spinner lewat `toolbarBusy`, hasil "Terkirim ke …" di slot teks toolbar) + bagian **"Tujuan chat"** di Setelan (grup per perangkat serial mono, subjudul package, hapus ✕ dua klik memakai `askConfirm` yang sudah ada). Verifikasi: `cargo check` lolos, `cargo test` **63 lolos** (2 ignored; tes baru di `chat_target.rs`: urutan baris, package/bounds tak terpakai tidak pernah ditawarkan, exact-match menolak dobel, decoding entity, bounds rusak, dump terpotong, `send_button` butuh tepat satu kandidat) + tes parsing fokus di `clipboard_image.rs`, `npm run check` 0 error, `npm run build` sukses. **Belum diuji end-to-end dari tombol Ctrl+V fisik di aplikasi (jalankan mulai dari chat "Pesan ke diri sendiri" supaya tidak ada pesan sungguhan ke orang lain): `/id/send` belum pernah terlihat pada layar caption WhatsApp nyata, jadi urutan tap-baris-then-tap-kirim masih spekulatif, dan jalur Wi-Fi belum diukur terhadap `Deadline`.** Catatan risiko untuk pengguna: HP tidak boleh disentuh ±3,5–7 dtk setelah Ctrl+V (kita sedang membaca dan mengetuk daftar di HP; layar yang berubah di tengah jalan membuat YAOP berhenti tanpa mengirim), dan perubahan WhatsApp bisa mengganti `resource-id` picker → fitur mundur ke mode chip, tidak pernah mengetuk buta. 13 file `yaop-clipboard-*.png` hasil probe masih tertinggal di `/sdcard/Download` HP (belum dihapus — menunggu keputusan pengguna).
